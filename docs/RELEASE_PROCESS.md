# 发布、升级与回滚

## 1. 环境

- 开发：虚构数据，可频繁重置。
- 测试：CI 临时数据。
- 预发布：正式数据的脱敏副本或完整备份副本。
- 正式：用户确认后升级。

## 2. 版本

使用语义化版本：

- MAJOR：不可兼容的数据或产品变化；
- MINOR：向后兼容功能；
- PATCH：缺陷修复。

数据库 Schema、业务规则、提示词和 AI Schema 分别有独立版本号。

## 3. 发布候选

1. 从 `develop` 创建 `release/x.y.z`；
2. 冻结新增功能；
3. 执行全量测试、迁移和恢复演练；
4. 生成安装包和校验哈希；
5. 生成 `templates/RELEASE_REPORT.md`；
6. 产品所有者在预发布环境验收；
7. 合并到 `main` 并打标签。

## 4. 正式升级

```text
停止写入 → 创建完整备份 → 校验备份
→ 执行程序和数据库升级 → 健康检查
→ 核心流程烟雾测试 → 启用正式写入
```

## 5. 自动回滚触发

- 数据库迁移异常；
- 备份校验失败；
- 核心健康检查失败；
- 关键表记录数量异常变化；
- 文件引用大量失效；
- 应用无法启动或核心 E2E 失败。

## 6. 回滚

```text
停止服务 → 保存故障现场 → 恢复旧程序
→ 恢复数据库和文件 → 运行一致性检查
→ 重新启用 → 生成事故报告
```

禁止在正式库上不断试改直到成功。
