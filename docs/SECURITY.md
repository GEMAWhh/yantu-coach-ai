# 安全与数据保护

## 1. 威胁模型

重点风险：

- API Key 泄漏；
- 上传文件伪装、路径穿越和恶意 PDF；
- AI 草稿越权写入正式数据；
- 数据库迁移或恢复造成数据丢失；
- 开发环境误用正式数据；
- 日志泄露题目、笔记和个人信息；
- 本地服务意外监听局域网；
- 依赖供应链漏洞。

## 2. 密钥

- 密钥只保存在后端环境变量或操作系统安全存储；
- 前端只显示“已配置/未配置”；
- 日志、错误信息、导出和备份清单不得出现完整密钥；
- 仓库启用 secret scanning；
- `.env` 永不提交。

## 3. 本地服务

- 默认绑定 `127.0.0.1`；
- CORS 只允许明确前端 Origin；
- 桌面封装后使用随机会话令牌；
- 禁止未授权的局域网访问。

## 4. 文件上传

- 同时校验扩展名、MIME 和文件头；
- 设置单文件和总容量限制；
- 服务端生成存储名；
- 路径规范化并阻止 `..`；
- 图片解码失败拒绝；
- PDF 不执行脚本、嵌入文件和外部链接；
- 使用 SHA-256 去重和完整性校验。

## 5. 删除与恢复

- 默认软删除；
- 永久删除必须二次确认并生成审计事件；
- 删除原文件前检查全部引用；
- 重大删除前创建备份；
- 恢复操作先备份当前状态。

## 6. 环境隔离

`data/dev`, `data/test`, `data/prod` 使用不同绝对目录和数据库。测试启动时若检测到正式目录立即失败。

## 7. 依赖安全

- 锁定依赖版本；
- Dependabot 或同类工具生成更新 PR；
- 更新必须通过完整测试；
- 高危漏洞阻止发布；
- 不自动合并重大版本升级。

## 8. 日志

允许记录对象 ID、操作、状态和错误码；默认不记录完整题干、笔记、图片内容和认证信息。调试日志必须可关闭并有保留期限。
