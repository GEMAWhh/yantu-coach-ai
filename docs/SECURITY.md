# 安全与数据保护

## 1. 威胁模型

重点风险：

- API Key 泄漏；
- 上传文件伪装、路径穿越和恶意 PDF；
- AI 草稿越权写入正式数据；
- 数据库迁移或恢复造成数据丢失；
- 开发环境误用正式数据；
- 日志泄露题目、笔记和个人信息；
- 本地服务意外监听局域网；
- 依赖供应链漏洞。

## 2. 密钥

- 密钥只保存在后端环境变量或操作系统安全存储；
- 前端只显示“已配置/未配置”；
- 日志、错误信息、导出和备份清单不得出现完整密钥；
- 仓库启用 secret scanning；
- `.env` 永不提交。

## 3. 本地服务

- 默认绑定 `127.0.0.1`；
- CORS 只允许明确前端 Origin；
- 桌面封装后使用随机会话令牌；
- 禁止未授权的局域网访问。

## 3.1 云端个人版连接边界

- Web 构建通过 `VITE_YANTU_API_BASE_URL` 指向独立 API；该变量只能包含公开 API Origin，不得包含密钥、凭据、路径或查询参数；
- API 通过 `YANTU_CORS_ALLOWED_ORIGINS` 配置明确的前端 Origin；禁止 `*`；
- 未配置允许 Origin 的生产 API 不返回跨域许可；
- CORS 不是身份认证；公开部署时必须同时启用下方的个人访问密钥；
- 未来扩展为多用户时，应替换为安全会话或短期令牌，并保持用户数据服务端隔离。

当前云端个人版按 `ADR-0005` 使用个人访问密钥作为第一阶段认证：

- 生产环境必须配置 `YANTU_AUTH_TOKEN_SHA256`，缺失时服务拒绝启动；
- 使用 `python scripts/hash_auth_token.py` 在本地生成摘要，原始密钥不得进入命令历史、仓库或日志；
- Web 仅将原始密钥放入当前标签页的 `sessionStorage`，关闭会话后需重新输入；
- 此方案只适用于当前单用户阶段，不视为多用户账号系统；
- 对公网正式开放前仍需在部署层配置 HTTPS、请求速率限制和日志脱敏。

云端 PostgreSQL 运行时按 `ADR-0006` 执行：

- 生产环境必须配置 TLS `YANTU_DATABASE_URL`，且只能使用 PostgreSQL；SQLite URL 会在启动前被拒绝；
- 数据库 URL、密码和 Supabase 密钥只配置在部署平台的私密环境变量中，不得提交、打印或粘贴到 Issue、PR、聊天和截图；
- Render 的本地磁盘是临时介质，禁止将它用于结构化正式数据、上传原件或唯一备份；
- Supabase Storage bucket 必须保持私有；Secret Key 只允许配置在 FastAPI 部署环境，禁止放入 Web 构建变量、浏览器存储、GitHub、日志、截图或聊天；
- 未配置对象存储时，生产 PostgreSQL 模式会拒绝原件和证据上传；配置后由服务端以内容哈希路径访问私有 bucket，网络或服务失败时回滚新元数据事务；
- 云端备份恢复尚未完成前，不得将当前导出或备份能力视为云端持久化；生产 PostgreSQL 模式会继续拒绝备份、恢复、完整导出及本地个人设置读写；
- 上述拒绝或服务异常响应只返回稳定的 `CLOUD_FILE_STORAGE_NOT_READY`、`CLOUD_FILE_STORAGE_UNAVAILABLE`、`CLOUD_BACKUP_NOT_READY` 或 `CLOUD_SETTINGS_NOT_READY` 错误码，不泄露本地路径、连接信息或密钥。

## 4. 文件上传

- 同时校验扩展名、MIME 和文件头；
- 设置单文件和总容量限制；
- 服务端生成存储名；
- 路径规范化并阻止 `..`；
- 图片解码失败拒绝；
- PDF 不执行脚本、嵌入文件和外部链接；
- 使用 SHA-256 去重和完整性校验。

## 5. 删除与恢复

- 默认软删除；
- 永久删除必须二次确认并生成审计事件；
- 删除原文件前检查全部引用；
- 重大删除前创建备份；
- 恢复操作先备份当前状态。

## 6. 环境隔离

`data/dev`, `data/test`, `data/prod` 使用不同绝对目录和数据库。测试启动时若检测到正式目录立即失败。

## 7. 依赖安全

- 锁定依赖版本；
- Dependabot 或同类工具生成更新 PR；
- 更新必须通过完整测试；
- 高危漏洞阻止发布；
- 不自动合并重大版本升级。

## 8. 日志

允许记录对象 ID、操作、状态和错误码；默认不记录完整题干、笔记、图片内容和认证信息。调试日志必须可关闭并有保留期限。
