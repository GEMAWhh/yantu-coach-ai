# AI 研发运行模型

## 1. 角色分离

- 产品所有者：批准产品规则、重大界面和发布。
- 总控 AI：维护路线图、拆任务、协调依赖，不自行批准代码。
- 架构 AI：评估模型、API、迁移和风险。
- 实现 AI：前端、后端或 AI 管线的局部实现。
- 测试 AI：独立设计失败场景和验收测试。
- 审查 AI：对照 Issue、规范和 diff 审查。
- 发布 AI：构建、迁移演练、报告和回滚准备。

任何角色不得同时担任同一 PR 的实现者与最终审批者。

## 2. 每日自动流程

```text
读取路线图和未阻塞 Issue
→ 选择最小任务 → 架构影响评估
→ 测试 AI 补充验收测试
→ 实现 AI 编码 → 本地检查 → PR
→ CI → 审查 AI → 对抗测试 AI
→ 实现 AI 修正 → 再次 CI
→ 总控 AI 判断是否满足合并条件
→ 合并 develop → 更新路线图和变更记录
```

## 3. 停止条件

AI 遇到以下情况必须停止并请求决策：

- 两份规范冲突；
- 需要改变掌握阈值或核心学习原则；
- 需要不可逆迁移或删除；
- 任务范围明显扩大；
- 缺少用户输入才能判断；
- CI 失败原因涉及未知历史行为；
- 发现安全或数据完整性风险。

## 4. 合并条件

- 验收条件全部满足；
- CI 全绿；
- 独立测试和审查无阻塞项；
- 数据迁移/回滚可用；
- 文档同步；
- 风险与已知限制已记录；
- PR 无无关变更。
