# 产品规格｜考研智能学习系统

## 1. 产品定位

系统是一套本地优先、长期使用的 AI 考研学习规划与辅导平台。它不是资料后台、待办清单或单一聊天窗口，而是围绕以下闭环运行：

```text
长期目标 → 多层计划 → 知识诊断 → 理解与主动回忆
→ 基础应用与变式迁移 → 每日执行 → 证据反馈
→ 用户确认 → 掌握判定与错因修正 → 间隔复习 → 动态再计划
```

当前主要场景：数学一 + 专业课 841，目标为大连理工大学控制科学与工程学硕。后续允许扩展英语和政治。

## 2. 核心用户目标

- 每天明确知道做什么、为什么做、做到什么程度；
- 把学期、季度、月、周目标稳定分解到每日；
- 区分“看过”“会回忆”“能应用”“能迁移”“长期保持”；
- 把错题从图片变为结构化诊断和重做计划；
- 根据真实用时、正确率、把握度和未完成原因调整后续计划；
- 形成完整知识图谱和个人薄弱覆盖层；
- 获得基于证据的资深考研总教练式反馈。

## 3. 一级导航

1. **今日**：今日计划、执行记录、学习证据、AI 复盘。
2. **规划**：学期、季度、月、周、日目标及风险。
3. **学习**：资料、学习单元、题库、错题、复习卡片和知识图谱。
4. **进度**：计划偏差、掌握阶段、正确率、错因和风险。
5. **设置**：考试信息、学习画像、规则、AI 配置和数据管理。

## 4. 核心业务对象

- 用户画像与考试目标；
- 五层目标；
- 每日任务与任务结果；
- 标准知识节点与关联；
- 掌握证据和掌握快照；
- 到期复习；
- 学习资料与原始文件；
- 每日学习证据；
- 题目、作答、答案、解析与错题；
- AI 草稿、确认和审计记录；
- 备份、恢复和数据迁移记录。

## 5. 严格分离的状态

| 状态域 | 示例 | 说明 |
|---|---|---|
| 上传状态 | 待整理、已整理、已归档、已删除 | 只描述原始文件 |
| 学习单元状态 | 未开始、进行中、已完成、顺延、归档 | 描述学习单元执行 |
| 每日任务状态 | 待完成、进行中、已完成、跳过、撤回 | 描述当天动作 |
| 任务结果 | 完成、部分完成、做错、不会 | 描述真实结果 |
| 掌握阶段 | 未学习至稳定掌握/掌握衰退 | 由多类证据判定 |
| AI 内容状态 | 处理中、草稿、待修正、已确认、已拒绝、失败 | 未确认不进入正式库 |

## 6. 关键用户旅程

### 6.1 最小学习闭环

```text
建立周目标 → 选择知识点 → 前置诊断 → 理解与闭卷回忆
→ 基础练习 → 真实结果 → 状态判定 → 补救或复习 → 明日候选
```

### 6.2 每日证据闭环

```text
上传一张或多张照片 → 识别和结构化 → 待确认草稿
→ 用户修正/确认 → 正式学习记录 → 更新计划与掌握证据
```

### 6.3 错题闭环

```text
分类上传 → OCR/结构化草稿 → 用户确认 → 深层错因
→ 隔日无提示重做 → 同类变式 → 间隔复测 → 稳定修正
```

### 6.4 用户驱动的 Prompt 工具箱

系统提供版本化的题目讲解、错因诊断、资料整理和每日复盘 Prompt。用户填写学习材料，
生成并编辑最终 Prompt，复制后自行前往外部 LLM Chat 对话。系统不得自动发送内容，也不读取
或保存第三方模型回答；任何回答都不能直接更新任务、错题或掌握状态。

## 7. 不可接受的产品形态

- 以数据库字段、内部 ID 为主要界面；
- 将任务勾选等同于掌握；
- 将照片上传等同于完成；
- 将原题即时重做等同于错题解决；
- 大量按钮和操作同时暴露；
- 用通用鼓励代替教学诊断；
- 直接复制其他考生作息；
- 未经确认写入 AI 识别或 AI 生成内容；
- 前端保存 API Key；
- 正式数据只存于测试云环境。

## 8. 非功能要求

- **本地优先**：离线可完成核心计划、任务、反馈、复习和统计。
- **数据安全**：正式数据可备份和恢复；密钥不公开。
- **可追溯**：自动状态变化有证据、规则版本和理由。
- **可撤回**：计划大幅调整和 AI 正式写入可撤销。
- **移动端可用**：手机和平板无需横向宽表即可操作。
- **可降级**：AI 服务不可用时，确定性核心仍工作。
- **可测试**：关键业务规则必须可通过自动测试验证。

## 9. 首个正式版本范围

包含：

- Vue 前端和 FastAPI 本地后端；
- SQLite、文件目录和备份恢复；
- 周目标、今日任务、任务结果；
- 知识点状态机、证据、回退和间隔复习；
- 真实用时校准；
- localStorage 原型数据迁移；
- 核心流程 E2E。

当前后端已落地周目标、今日任务、任务结果的最小链路：任务保留来源追溯，
结果保存真实执行数据，任务完成不直接等同于掌握。今日计划引擎 V1 采用确定性规则，
在候选任务上执行单科过滤、精力适配、前置阻塞、机动时间保留、超时拆分和重复未完成诊断，
并为入选与拒绝任务返回评分来源和原因。
间隔复习调度 V1 已落地阶段基础间隔、到期候选、复习结果幂等、独立通过延长、
失败回退和同日重做不计独立时间点。
个人用时校准 V1 已落地按科目/任务类型/难度隔离的有界指数平滑系数、异常值忽略、
连续超时拆分建议，并在今日计划生成前校准候选任务预计用时。

不包含：

- 真实 OCR、多模态识别；
- AI 自动错因诊断；
- 完整知识图谱可视化；
- 联网校准；
- 云端多用户；
- Redis、Celery、Neo4j 和微服务。
