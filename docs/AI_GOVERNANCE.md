# AI 治理规范

## 1. 基本原则

- AI 是建议与结构化工具，不是正式数据的最终裁决者；
- 确定性业务规则优先于模型输出；
- AI 结果默认不可信，必须经过 Schema、业务规则和用户确认；
- 看不清时承认不确定，不得补造题干、公式、答案或用时；
- 模型不可用时系统核心闭环继续工作。

## 2. 标准生命周期

```text
原始输入 → AIJob → 原始响应 → JSON Schema 校验
→ 置信度与业务校验 → 待确认草稿 → 用户修正/确认
→ 正式应用服务 → 事务写入 → 审计记录
```

## 3. 事实分层

- `confirmed_facts`：由原始证据清晰支持，仍需用户确认。
- `inferences`：教学或结构化推断，必须明确标识。
- `uncertain_fields`：低置信度、遮挡、冲突或无法判断。
- `suggested_actions`：建议，不直接执行。

## 4. AI 不得直接执行

- 掌握阶段推进或回退；
- 错题标记已解决；
- 删除文件或正式记录；
- 大幅调整正式计划；
- 执行 SQL、数据库迁移和备份恢复；
- 修改考试目标；
- 发送网络请求到未经批准的服务；
- 将用户上传资料用于模型训练。

## 5. 模型与提示词注册

每次调用记录：

`provider, model_name, model_version, prompt_id, prompt_version, schema_version, temperature, created_at, source_ids, request_hash`

提示词必须在仓库中版本管理。更换模型或提示词后，必须运行黄金测试集并形成评测报告。

## 6. 置信度规则

- 关键字段低于阈值时不得自动填充；
- 题干、公式、日期、科目、答案等关键字段出现冲突时进入 `needs_correction`；
- 置信度不是“正确概率”的承诺，只用于路由到自动草稿或人工补充；
- 任何置信度均不能绕过用户确认。

## 7. 输出结构

每日复盘统一六部分：

1. 已确认事实；
2. 教学判断；
3. 当前风险；
4. 调整理由；
5. 具体任务与验收标准；
6. 需要确认。

## 8. AI 评测门槛

- 非法正式写入次数必须为 0；
- 确定事实误报率须低于项目配置门槛；
- 不确定字段召回优先于“多识别”；
- 模型升级不得降低关键字段准确率或安全拒绝能力；
- 失败样本必须进入回归测试集。
