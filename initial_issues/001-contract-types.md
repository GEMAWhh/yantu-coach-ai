# 阶段0：建立共享 API 契约与错误模型


## 背景

前后端 AI 并行开发必须先冻结基础 DTO、错误结构、分页、幂等和版本冲突规则。

## 目标

实现 OpenAPI 基础配置、统一错误响应、请求 ID、版本冲突和前端生成/手写 typed client 骨架。

## 非目标

不实现具体学习业务接口。

## 验收标准

- [ ] `/health` 和 `/api/v1/meta` 符合统一响应。
- [ ] 422/404/409/500 使用统一错误结构。
- [ ] 每次请求有 request_id。
- [ ] 前端可通过 typed client 调用 health。
- [ ] 契约测试覆盖错误结构。

## 测试要求

API 集成测试验证正常、验证失败和版本冲突。

## 回滚

移除中间件和客户端生成配置，不影响数据。
